# 项目愿景 · 风后奇门手势交互模拟器

这份文件描述设计目标，并不代表所有目标已经实现或通过真人测试。实现证据和当前限制见 [CURRENT_STATUS.md](CURRENT_STATUS.md)，开发交接见 [COLLABORATOR_HANDOFF.md](COLLABORATOR_HANDOFF.md)。

## 核心体验

以《一人之下》中王也风后奇门的空间与术式感为灵感，用原创程序化图形实现一个浏览器手势交互实验。用户坐在或站在普通电脑 RGB 摄像头前，主要依靠上半身和双手操纵身前的悬浮阵局。

目标操作链：

```text
张掌召阵 → 操纵四盘 → 指宫 → 捏合锁定 → 阵局对位、蓄势
→ READY → 新的施术动作 → 术法由阵局释放 → 换宫、再次施术 → 握拳收阵
```

真实交互是核心；自动演示、键盘调试和 Showcase 用于开发与展示，不作为真人成功率证据。

## 掌中生阵与正面悬浮

张开一只手掌后，掌心出现小型能量核心和微型圆阵；圆阵沿视觉深度离开掌心，在胸前偏前方展开。阵盘完成展开后稳定悬浮，只有明确的抓取手势才能改变整体位置。

默认是 `FRONT_CIRCLE`：面向用户、近似完整圆形，保留轻微透视、呼吸、视差和前后层差。阵局是三维空间结构，不是固定屏幕图片。常态下完整圆阵应清晰可见，双手撑开后外环可以接近或超出画面边缘。

不需要脚、腿、全身 Pose 或地面追踪；脚下领域不属于当前目标。`GROUND_DOMAIN` 只能作为将来的实验方向，不应与默认体验混用。

## 四盘操纵

地盘、人盘、天盘、神盘各有自己的文字、符纹和结构，沿视线方向形成可辨识的薄层。支持或计划继续完善：

- 靠近盘层时 Hover 响应，提示将要抓取哪一层。
- 捏合抓取、腕部拨盘、其它层随动，松手后惯性与宫位吸附。
- 能量丝连接手指与被操纵层，盘层局部亮起和前移。
- 双手撑开或压缩空间，调整大小；双手捏合移动与倾斜阵局。
- 双手拉开时结构化 Split，靠近时分层合拢。

操作应有轻微滞后、惯性、张力和落位反馈，表现重量感，同时避免过度平滑造成延迟。

## 八宫指向与锁定：最高交互优先级

```text
POINT → TARGET_PREVIEW → TARGET_FOCUSED → TARGET_ARMED
→ 新 PINCH_DOWN_EDGE → LOCK_CANDIDATE → LOCKED
```

食指尖与 Aim Cursor 在镜像预览中应基本重合；宫位迅速响应，再根据手速和距边界的距离稳定 Focus。Focus 后保存 Armed Target，允许食指自然弯曲、POINT 消失，然后完成拇指食指捏合。

有 Armed Target 时，新捏合用于锁宫；不能被普通抓盘、ROTATE 或双手操作抢走。没有 Armed Target 时，普通捏合仍可操盘。锁宫成功后高亮、浮起符号、中心到目标宫的能量路径，以及右上角独立的目标宫位／锁定宫位／术式状态共同反馈。

历史真人测试出现过指向高置信但 Focus 慢、捏合进入 ROTATE、目标丢失、Spell 一直为 NONE。这些问题需要在正确构建版本上重新验收。

设计目标（尚非实测结论）：预览尽量 ≤100ms、稳定指向到 Focus 尽量 ≤150ms、有效捏合到 Lock 尽量 ≤150ms；连续真人锁宫成功率目标 ≥90%。

## 四术与合法发动

| 宫位 | 术式 | 目标动作与体验 |
| --- | --- | --- |
| 坤 | `KUN_EARTH` | READY 后重新准备张掌，轻 PUSH；阵纹延伸，再产生厚重土石／能量结构冲击。 |
| 巽 | `XUN_WIND` | READY 后新的短促横向 SWIPE；风流方向与镜像画面里的真实挥手方向一致。 |
| 震 | `ZHEN_LIGHTNING` | 锁宫 PINCH 周期完全结束；READY 后新的捏合蓄势、快速弹开，释放集中短促雷电。 |
| 坎 | `KAN_WATER` | 锁宫后松开，READY 后建立张掌 Neutral，再向身体方向轻 PULL；能量回流形成连续水流。 |

四术应该各有施术前兆、阵盘响应、充能、释放、镜头反馈、残留、冷却和恢复。效果从中心经目标宫产生，手是发动器。不能只换粒子颜色，也不能由锁宫残留动作或 READY 前的旧缓冲意外施法。

轻推、轻拉以约 5–15cm 的自然动作作为体验目标；横扫约一到两个手掌宽。真人数据未确认前不能为了达成目标随意降低阈值。其它四宫及组合术式属于未来扩展。

## 技术路线与视觉原则

TypeScript + Vite；MediaPipe Hand Landmarker 在浏览器本机识别，Three.js / WebGL 负责三维阵盘、原创 Geometry、Line、Canvas 纹理、Shader 和对象池特效。

镜像、预览裁剪、掌心锚点、瞄准和术法方向要共用坐标转换。手部追踪使用新摄像头样本时钟；渲染 RAF 不能把旧 landmarks 重新当作动作证据。

画面以暗青、墨黑、灰白、暗金和青白能量为主。圆阵轮廓、八宫和四盘层次清晰，常态能量流克制；抓取、锁宫和发动时才突出重点。避免横线、扫描仪表和密集 HUD 抢走人／手／阵的主体。

Bloom、扭曲、曝光与镜头冲击应可插拔、有预算；手部真实遮挡、体积感、声音与电影级特效需要后续单独实现和验证。质量配置里存在某字段，不代表对应效果已经接入。

## 可用性与性能目标

面向普通笔记本 RGB 摄像头和中端电脑，争取 Three.js 50–60 FPS、Hands 25–30 FPS。目标应结合设备、光照、距离和实际负载报告，不能用模拟时钟测试代替。

优先保证手掌跟随、拨盘响应、合法锁宫与施术，再按 PerformanceGovernor 降低视觉成本。资源必须复用并释放，监听器不能重复注册。弱光、轻微手抖、短暂遮挡、丢手和重复帧不能造成错误收阵、重复 CAST 或永久卡住。

QA 应明确区分实际摄像头、模拟输入和视觉演示。延迟、成功率、误触率需要真人动作和计数依据；CPU 样本到事件派发耗时不能冒充手到画面的物理延迟。

## 后续顺序与开源边界

先确保可安装运行，再验收 Target/Lock、完善可靠的 Lock/READY 反馈、连续四术真人测试；核心链稳定后再进行手部遮挡、空间深度、正式音效、电影级视觉和作品展示。更完整八宫规则、术式组合、部署和便捷校准是后续规划。
